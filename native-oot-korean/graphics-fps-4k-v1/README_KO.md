# 오카리나 그래픽 복구 v2

초록색 과발광·검은 영역·13FPS가 보인다는 보고에 대응하는 복구본입니다.
원인은 사진만으로 확정되지 않았습니다. FPS와 내부 4K 설정을 그대로 둔 채 텍스처 셰이더 변경을 되돌려 비교합니다.

게임을 종료하고 새로 받은 `Ocarina_Graphics_FPS_4K_Update.exe`를 실행한 뒤 **기존 OcarinaRecomp 설치 폴더**를 선택하세요.
파일 이름은 같지만 창 제목과 파일 버전은 **그래픽 복구 v2 / 0.2.6-recovery-v2**입니다.
`ferramentas`, `runtime`, `generated`, `build`가 들어 있는 폴더를 선택합니다.
재설치하거나 NUP를 다시 선택할 필요가 없습니다.

## 복구 내용

- 이번 업데이트에서 가져왔던 텍스처 미분·원자 연산 임시 레지스터 처리와 여러 텍스처 버퍼의 gather 변경을 이전 ko2 코드로 되돌립니다.
- 300FPS 목표·제한 해제·내부 4K 기능과 현재 FPS·해상도 설정을 유지합니다.
- 설정 파일의 fps_limit·oot_resolution 항목은 변경하거나 추가하지 않습니다.
- 오카리나 컨트롤러 진동 조회 수정, 기존 FSEL·링크·가변 gather와 조건부 EXIT 읽기 보정은 유지합니다.
- 저장 파일·언어·컨트롤러 매핑은 바꾸지 않습니다. 추가 색 보정은 기본값이며, 추가 선명화는 끕니다.
- 다음 게임 실행부터 프레임 측정 로그를 남깁니다. 별도의 전송이나 업로드는 하지 않습니다.

게임 메뉴의 300FPS·제한 없음·내부 4K 선택지는 그대로 남습니다. 실제 300FPS 성능은 확인되지 않았습니다.
같은 장소에서 초록색·검은 영역과 FPS를 확인하세요.

## 원인 확인에 필요한 로그

복구 적용 뒤 같은 장소에서 잠시 플레이하고 게임을 종료하세요.
설치 폴더의 **`ultima-partida-erros.log`** 파일을 보내주면 실제 렌더 타깃 크기·GPU 대기·셰이더 오류를 확인할 수 있습니다.
로그는 자동으로 전송되지 않습니다.

실제 게임 화면과 성능의 복구 여부는 아직 검증 전입니다. 이 도구는 원인 확정이나 모든 그래픽 오류 해결을 뜻하지 않습니다.

## 백업과 실패 복구

변경 전 실행 파일·소스·설정은 `build/oot111/graphics-4k-backup/날짜/`에 보관합니다.
컴파일 또는 실행 파일 연결 검사 실패 시 시작 전 파일로 자동 복원합니다.
이미 v1을 적용한 설치와 ko2 설치를 지원하며, 알려지지 않은 소스 변경은 덮어쓰지 않습니다.
빌드 로그는 `build/oot111/ocarina-graphics-4k-build.log`입니다.

## 소스와 재현

이 EXE는 게임을 포함하지 않으며, 설치된 컴파일러와 사용자가 소유한 기존 게임으로 로컬 빌드를 만듭니다.
`payload/`가 실제 배포 소스입니다. 개발 소스의 실험적 텍스처 변경 두 가지는 이번 payload에서 사용하지 않습니다.
`tools/oot/make_graphics_4k_update.py --base <변경 전 ko2 소스>`가 이전 셰이더 원문과 허용할 v1 해시를 묶습니다.
`source/`에는 대응 도구와 검증 코드, LICENSE·THIRD_PARTY_NOTICES가 있습니다.

- 원본: https://github.com/sostenesfreitas/ocarina-recomp/tree/fe7a9399a6daa5a789e7557e5a193db8f3055c2a
- 비교했던 Lichii: https://github.com/zortos293/Lichii/tree/bf4c42e223d4812d4456d3d8f66d892571d19a13
- 한국어 포트 및 복구 소스: https://github.com/jinju151203/Lichii/tree/codex/oot-korean-native/native-oot-korean

설치된 격리 Python의 보조 파일 검색 경로 수정도 포함합니다.
게임 데이터·생성된 게임 C·저장 파일·개인 로그는 배포하지 않습니다.

## 소스 검증

아래 패치는 기존 ko2 한국어 소스에 대응하는 개발 소스와 복구 패키지 제작 도구입니다. 실제 복구 배포물은 `make_graphics_4k_update.py --base <변경 전 ko2>`가 묶는 `payload/`입니다. 실험적 텍스처 백포트 두 가지를 포함한 개발 런타임을 그대로 빌드하는 것은 복구 프로필과 다릅니다.

검증: 실제 배포 셰이더 조합의 Windows x64 컴파일, 실제 capture 헤더 2,823개 검사, 300FPS·4K 시간/배율 처리, 7개 업데이트·백업·실패 복구·설정 보존 검사, 압축된 스크립트의 격리 실행과 PowerShell 구문 검사 통과. 실게임 그래픽과 실제 300FPS·4K 성능은 미검증입니다.
